## Performance Analysis

### Non-CF sites: why is py ~1.5x faster?

For sites with no Cloudflare protection, flaresolverr-rs averages **~2.4s** vs flaresolverr-py's **~1.7s**.
The gap is not TLS crypto overhead (confirmed: debug and release builds produce identical latency).

Root causes:

| Factor | flaresolverr-rs | flaresolverr-py |
|--------|----------------|----------------|
| HTTP client | reqwest (direct, same process) | Chrome inside Docker/Linux |
| Completion signal | Full response body downloaded | DOMContentLoaded event fired |
| Page load | Downloads entire HTML body | Stops when DOM is ready; skips lazy resources |
| Networking | Windows native TCP stack | Linux kernel TCP stack (Docker) |

Chrome fires its completion event at `DOMContentLoaded`, which can be significantly earlier than the server finishing the chunked transfer of the full body. reqwest reports done only after the complete body is received. For pages with deferred JavaScript or slow-closing connections this difference is consistently 0.5–1.5s.

### CF sites: rs is dramatically faster

For CF-protected sites (🍪 rows), rs averages **~3.1s** vs py's **~11.5s**. Reason: rs caches the `cf_clearance` cookie in the chaser-cf browser context and reuses it across runs. py re-solves the Turnstile challenge on every request.
